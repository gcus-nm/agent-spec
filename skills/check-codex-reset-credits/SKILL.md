# Codexリセット権を確認する

## 実行する

1. `bash`、`curl`、`jq`が利用できることを確認する。
2. 認証ファイルを既定の`${CODEX_HOME:-$HOME/.codex}/auth.json`から読む。別の場所なら
   `--auth-file <path>`を渡す。
3. 次を実行する。

```bash
bash scripts/check-codex-reset-credits.sh
```

4. 利用可能数と、各リセット権の状態、付与日時、有効期限を報告する。日時は実行環境の
   ローカルタイムゾーンで表示される。

JSONを後続処理へ渡す場合だけ`--json`を付ける。

```bash
bash scripts/check-codex-reset-credits.sh --json
```

終了コードは、`0`が成功、`2`が引数エラー、`3`が依存コマンドまたは認証の不足、`4`が
API取得失敗、`5`がレスポンス形式不正を表す。

## 安全条件を守る

- 読み取り専用のGETだけを実行し、リセット権を消費するAPIを呼ばない。
- アクセストークン、アカウントID、`auth.json`の内容を出力、ログ、成果物へ残さない。
- 認証ヘッダーの送信先をスクリプト内の`https://chatgpt.com`から変更しない。
- 認証ファイルが存在しない、必須値がない、APIが失敗する、またはレスポンス形式が不正な
  場合は推測せず停止し、再ログインまたはCodexの状態確認を案内する。
- このエンドポイントは公開仕様として保証されていないため、失敗時にリクエスト形式を
  推測して拡張しない。Codex本体のアカウント表示または読み取り専用APIを代替にする。
