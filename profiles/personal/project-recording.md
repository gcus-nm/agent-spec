# プロジェクト記録設定

履歴損失と後追い記録のずれを防ぐため、永続性のある情報は作業内容が新鮮なうちに記録します。

- 既存のプロジェクト `AGENTS.md` と記録方式を適用範囲に応じて確認し、既存の正本を優先します。
- 将来も有効なプロジェクト固有の規則、重要な判断、再発見コストが高い注意点が判明したら、
  作業中に `AGENTS.md` または適切な設計・運用文書を作成・更新します。
- 利用者に影響する変更、移行、運用変更、既知の制約は、作業中に `CHANGELOG.md` または
  プロジェクト既定の履歴へ記録します。既存の記録がなければ、将来追跡する価値がある場合に
  最小の記録を作成します。
- 既存の履歴と競合する別のログを作らず、完了前に記録と実際の変更内容が一致するか確認します。
- 一時的な調査メモ、秘密情報、生成物、生の差分、Git履歴だけで十分に追える低水準の事実は
  永続記録へ追加しません。
- 恒久ルールは `AGENTS.md`、時系列の履歴は `CHANGELOG.md` または専用記録へ分けます。

## Gitコミットメッセージ

実際にコミットを作成する場合だけ適用します。

- 件名は `<type>: <日本語の要約>` とします。
- `type` は `feat`、`fix`、`docs`、`refactor`、`test`、`chore`、`perf`、`build`、
  `ci`、`style`、`revert` から選びます。
- 例: `feat: ユーザー検索機能を追加`
