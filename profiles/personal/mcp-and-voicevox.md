# ツール選択と音声通知

この文書は、ツール選択が不明な作業、対象プロジェクトで専用ツールが有効な作業、または
ユーザーが音声通知を明示した場合だけ読みます。ツール一覧を通常タスクの常時コンテキストへ
入れません。

## 基本方針

- ローカルファイル操作、検索、ビルド、テスト、Git操作には、標準ツールとシェルを使います。
- 最初の結果が十分なら、同等の情報を返す複数ツールを重複して呼びません。
- MCPは固有能力が明確に有効な場合だけ使い、大きなツールスキーマは必要なプロジェクトまたは
  タスクだけで有効化します。
- 反復可能な複数ステップはSkill、決定的なローカル処理はCLIまたはスクリプト、外部データや
  対話的な外部操作はMCPまたはコネクターを選びます。

## 使い分け

| 対象 | 優先する手段 | 適用条件 |
|---|---|---|
| 小規模な既知ファイル | `rg`、標準ファイル操作 | 対象パスが既知、短いファイル、単一修正 |
| 大規模コード探索 | Serena | シンボル探索、参照元解析、複数ファイルのナビゲーション |
| Unity | Unity CLI Loopと対応Skill | コンパイル、対象ログ、テスト、Play Mode、Editor操作、画面確認 |
| 外部SDK・CLI | 導入版確認後にContext7 CLIと対応Skill | 現在の仕様が必要な場合。重要事項は公式資料やローカルコードでも確認 |
| 再現可能なWeb操作 | Playwright CLIと対応Skill | E2E、テスト修正、スクリーンショット、反復操作 |
| 未知のWeb UI探索 | Playwright MCP | 対話的に状態を探索する必要がある場合だけ |
| ローカルGit | `git` CLI | 状態、差分、履歴 |
| GitHub | GitHub MCPまたはコネクター | PR、Issue、レビュー、コメント、チェック状態 |

Unity CLI Loopでは、対象期間・ログ種別・件数を絞り、コード変更後に全ログを無条件取得しません。
Serenaメモリには、再発見コストが高く長期的に安定した情報だけを保存します。Context7利用前は
lockfile、manifest、プロジェクト設定、実コードから導入版を確認します。GitHub Actionsログは
失敗したジョブと必要範囲だけを取得します。

標準機能や既存正本と重複しやすいため、明確な理由がなければFilesystem、Git、Memory、
Sequential Thinking、Fetchの各MCPを追加せず、Playwright MCPも常時接続しません。

## VOICEVOX

音声通知は、ユーザーが明示的に要求した場合、対応Skillが明示起動された場合、または長時間
作業向け通知が明示的に有効な場合だけ行います。受領・開始・作業中・進捗・完了を全タスクで
多段通知しません。

- `speaker=29`、`speedScale=1.1` を使用します。
- 1回100文字以内にし、英単語は自然なカタカナへ調整します。
- エンジンへ接続できなくても作業を止めず、音声通知を要求された場合だけ失敗を報告します。
