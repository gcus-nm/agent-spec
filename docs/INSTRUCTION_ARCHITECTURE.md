# 指示アーキテクチャ

## 目的

すべての指示を1つのAGENTS.mdへ詰め込まず、適用範囲と利用場面に応じて分離します。
ルートファイルは索引として働き、エージェントはタスクに必要な文書だけを追加で読みます。

## レイヤー

| レイヤー | 内容 | 自動適用 |
|---|---|---|
| 環境ルート | 個人または汎用の読込ルーター | 環境による |
| プロジェクトAGENTS | チーム・コードベース固有の不変条件 | 対応エージェントでは自動 |
| nested AGENTS | サブシステム固有の上書き | 対応エージェントでは自動 |
| `instructions/core` | ベンダー非依存の基本原則 | ルーターが明示的に読込 |
| `instructions/use-cases` | タスク種別の手順 | 該当時だけ読込 |
| `profiles` | 個人の言語・通知・ツール嗜好 | 選択した利用者だけ読込 |
| `adapters` | 製品ごとの自動読込形式と導入差分 | 対象製品の導入時に参照 |
| `templates` | 導入時にコピーして具体化するひな形 | コピー後に適用 |
| `skills` | 反復可能な手順、参照資料、任意スクリプト | 明示起動または説明との一致時 |
| `.serena/memories` | Serena用の索引・長期知識 | 必要時に読込 |

この構成自体を変更するときの同期・検証規則は `docs/MAINTENANCE.md` を正本とします。

## 読込順

1. システム・開発者・ユーザーの明示指示
2. 環境ルートのルーター
3. 汎用コア
4. 選択された個人プロファイル
5. プロジェクトルートから対象へ近づく順の指示
6. 該当ユースケース文書
7. 明示起動または依頼内容に一致したSkill本文と必要なリソース

同じ階層で矛盾した場合は、対象に近く具体的な指示を優先します。Codexの実際の自動探索は
ルートから現在地へAGENTSファイルを連結し、近い指示を後に配置します。参照先Markdownは
自動では読み込まれないため、ルーターに明示的な読取指示を置きます。

SkillはAGENTSの優先順位を置き換えるものではありません。Skillは反復する作業手順として
上位指示と対象プロジェクトの制約に従います。`instructions/use-cases/`は短い共有ガイド、
Skillは明確な起動条件、入出力、必要に応じたスクリプトや参照資料を持つワークフローとして
使い分けます。Skillの構造と配布は`docs/SKILL_MANAGEMENT.md`を正本とします。

## 肥大化を防ぐ基準

- ルートAGENTSは索引、常時ルール、正確なコマンド、完了条件だけにします。
- 1つの規則が特定タスク・技術・利用者だけに適用されるなら別ファイルへ移します。
- 時系列ログは `docs/CHANGELOG.md`、意思決定はADR、運用手順はRunbookへ分けます。
- 外部仕様の説明を複製せず、必要なローカル要約と公式URLを持ちます。
- 指示の最大読込量に依存せず、重要なものほど短く入口に近く置きます。
