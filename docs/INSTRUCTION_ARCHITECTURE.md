# 指示アーキテクチャ

## 目的

通常タスクの初期コンテキストを、短い環境ルート、適用されるプロジェクト `AGENTS.md`、依頼に
明確に一致する追加文書またはSkillだけに保ちます。参照先Markdownは自動読込されないため、
入口には起動条件と正確なパスを残します。

## レイヤー

| レイヤー | 内容 | 読込条件 |
|---|---|---|
| 環境ルート | 個人設定、短い安全規則、条件付きルート | 環境により自動 |
| プロジェクトAGENTS | チーム・コードベース固有の不変条件 | 対応エージェントでは自動 |
| nested AGENTS | サブシステム固有の上書き | 対応エージェントでは自動 |
| `instructions/core` | 複雑・高リスク作業の詳細原則 | 明示条件に一致するときだけ |
| `instructions/use-cases` | 頻出タスクの詳細と特殊作業用索引 | 直接ルートまたはフォールバック |
| `profiles` | 技術、通知、ツールの個人設定 | 選択した利用者かつ条件一致時 |
| `adapters` | 製品固有の導入・設定・診断差分 | 対象製品の問題時だけ |
| `templates` | コピーして具体化する入口 | コピー後に適用 |
| `skills` | 反復可能なワークフロー | 明示起動または説明との一致時 |
| `.serena/memories` | 安定した非自明な長期知識 | Serena利用時かつ必要なとき |

## 通常の読込経路

```text
環境ルート
→ プロジェクトルートから対象までのAGENTS.md
→ 明示条件に一致した場合だけ追加文書またはSkill
```

`principles.md`、`task-lifecycle.md`、個人プロファイル詳細、ユースケース索引を通常タスクで
一律に読みません。個人用環境ルートは日本語、コマンド表記、短い安全・検証規則を直接持ち、
`profiles/personal/AGENTS.md`は旧ルートとの互換用入口に限定します。

## ルーティング

- コードレビュー、複雑な調査、大規模コード変更などの頻出タスクは、環境ルートから詳細文書へ
  直接ルーティングします。
- 大規模、曖昧、高リスク、横断的な変更や複雑な診断だけ、タスクライフサイクルを読みます。
- `AGENTS.md`や指示設計、Skill、`agent-spec`保守、製品固有問題は、それぞれの正本へ直接
  ルーティングします。
- 直接ルートがない特殊作業だけ `instructions/use-cases/README.md` を使います。
- 同じ実行環境で常時読む複数ファイルへ、同じルーティング表を複製しません。personalと
  genericの環境テンプレートは排他的な導入候補なので、それぞれに必要な入口を持ちます。

## CLI・Skill・MCP

- 標準ファイル操作とシェルは、ローカル検索、編集、ビルド、テスト、Gitに使います。
- CLIまたはスクリプトは、決定的で再現可能なローカル処理に使います。
- Skillは、明確な起動条件を持つ反復ワークフローに使います。
- MCPまたはコネクターは、外部データ、型付き外部操作、対話的探索など固有能力が必要な場合だけ
  使います。
- 同等の結果を返すツールを重複して呼ばず、大きなツールスキーマは必要なタスクだけで
  有効化します。

個人向けの具体的な使い分けは `profiles/personal/mcp-and-voicevox.md`、Skillの構造と配布は
`docs/SKILL_MANAGEMENT.md`を正本とします。

## 肥大化を防ぐ基準

- 入口には常時必要な短い規則と、「条件 → 正確なパス」だけを置きます。
- 特定の技術、利用者、タスクだけに適用する本文は条件付き文書またはSkillへ分けます。
- 時系列ログは `docs/CHANGELOG.md`、意思決定はADR、運用手順はRunbookへ分けます。
- 外部仕様を長く複製せず、必要なローカル要約と公式URLを持ちます。
- 常時読込ファイル数、ルーティング重複、過剰なツール候補をrepo検証で保護します。
