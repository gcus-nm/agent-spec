# 指示ドキュメント設計ガイド

## 置き場所をスコープで決める

| 内容 | 置き場所 |
|---|---|
| その会話だけの制約 | ユーザープロンプト |
| 個人の全プロジェクト共通設定 | グローバル指示または `profiles/` |
| チーム・リポジトリ共通規約 | リポジトリルート `AGENTS.md` |
| サブシステム固有規約 | 対象に近いディレクトリの `AGENTS.md` |
| 繰り返し使う手順 | Skillまたは `instructions/use-cases/` |
| 外部データ・操作 | MCPまたはコネクター |
| 機械的に強制できる規則 | テスト、リンター、型検査、フック |
| 安定した非自明なプロジェクト知識 | メモリまたは設計文書 |

## AGENTS.mdに残す内容

- リポジトリ構造と重要な入口
- 正確なセットアップ、ビルド、テスト、検証コマンド
- 常に守る設計・品質・セキュリティ制約
- PRやレビューの期待値
- 完了条件と、参照すべき詳細文書へのルーティング

## 分割する内容

- 特定の言語、フレームワーク、ディレクトリだけに適用する規則
- 計画、レビュー、リリース、調査など特定ユースケースの詳細手順
- 長いアーキテクチャ説明、API一覧、障害対応手順
- 個人の通知、口調、ツール選択、実験的ルール
- 時系列の作業日誌や、短期間で陳腐化する状態

## 条件付き指示へ導線を作る

- 参照先Markdownは自動で読み込まれると仮定せず、常時読む入口から読取条件と正確な
  相対パスを示します。
- 条件付き文書が複数ある場合は、入口から1つの短い索引へ導き、索引で
  「依頼条件 → 読む文書」を対応させます。
- 「関連文書」「該当ファイル」のように候補を特定できない案内だけを残しません。
- 指示を追加、移動、改名したときは、入口、索引、テンプレート、導入済みルート、
  検証スクリプトの参照を同期します。
- 常時読む本文へ詳細手順を複製せず、入口には起動条件と正本への導線だけを置きます。

## 書き方

- 曖昧な美辞麗句ではなく、観察可能な行動と完了条件を書きます。
- `常に`、`必ず`、`禁止`は、本当に全対象へ適用できる場合だけ使います。
- 正確なコマンドには、実行ディレクトリ、前提、成功条件を添えます。
- ルールには適用範囲を持たせ、重複した正本を作りません。
- 外部URLは根拠と更新確認先に使い、作業に必須の要点はローカルにも残します。

## 更新基準

- 同じ誤りやレビュー指摘が繰り返されたら追加候補にします。
- コードや自動検査で強制できるなら、文章だけで解決しません。
- 追加時に、既存規則との矛盾、重複、より狭い置き場所がないか確認します。
- 定期的に無効なコマンド、古いパス、完了済み移行ルールを削除します。
