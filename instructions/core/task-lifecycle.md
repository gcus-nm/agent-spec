# 複雑なタスクのライフサイクル

この文書は、大規模、曖昧、高リスク、横断的な変更、複雑な調査・診断、または明示的な計画が
必要な作業だけに適用します。小規模で対象と完了条件が明確な通常タスクでは読みません。

## 1. 契約と計画

- Goal、Context、Constraints、Done whenを整理します。
- 安全な仮定で進められる不足は補い、結果を大きく変える選択だけを確認します。
- 影響範囲、段階、検証方法、停止条件を実装前に明確にします。

## 2. コンテキストを絞る

- 対象に近い `AGENTS.md`、既存差分、候補ファイルやシンボルから先に確認します。
- `AGENTS.md`や指示設計の編集では [`instruction-authoring.md`](instruction-authoring.md)を読みます。
- 製品固有の導入、認証、権限、サンドボックス、ツール検出問題では
  [`adapters/README.md`](../../adapters/README.md)から対象製品を選びます。
- 直接ルートがない特殊作業だけ、[`instructions/use-cases/README.md`](../use-cases/README.md)を
  フォールバック索引として使います。
- 最新の外部仕様が必要なら公式文書や一次資料を確認します。

## 3. 実行と検証

- 小さく一貫した単位で変更し、公開API、データ、依存関係、移行、外部送信への影響を追跡します。
- 対象に対応するテスト、リンター、型検査、ビルドを実行し、最終差分を見直します。
- 実行できない検証は、理由、代替確認、残る不確実性を記録します。

### 本来の手段を実行できない場合

権限、認証、不足ツール、環境制約、外部状態により本来の手段を実行できない場合、代替実行前に
本来の手段、阻害要因、実行可能にする対応、代替案と差異を示します。結果を大きく変える代替は
ユーザーの選択を待ちます。あらかじめ許可された代替は、その範囲で進められます。

## 4. 引き渡す

- 達成した結果、主要変更、検証結果、未確認事項と残るリスクを示します。
- ユーザーが次に行う必要がある操作だけを案内します。
