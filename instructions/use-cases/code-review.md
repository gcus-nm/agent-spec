# コードレビュー

## 優先順位

1. 正しさ、データ損失、セキュリティ、権限
2. 互換性、回帰、並行性、エラー処理
3. テスト不足、運用・可観測性、性能
4. 保守性と、プロジェクトで明示されたスタイル

## 指摘の条件

- 変更によって新たに発生した、具体的で再現可能または論理的に説明できる問題を指摘します。
- 問題が起きる入力、環境、実行経路を示します。
- 行範囲を絞り、修正可能な単位で説明します。
- 単なる好みや、既存コード全体にある無関係な問題は混ぜません。
- 問題がなければ明確に伝え、残るテスト上の不確実性だけを補足します。

レビュー依頼では、要約より指摘を先にし、重大度順に並べます。
