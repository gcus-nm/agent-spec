# コード変更

1. 対象に近い指示、既存差分、関連テストを確認します。
2. 現行挙動と変更後の完了条件を明確にします。
3. 公開API、データ、依存関係、セキュリティへの影響を確認します。
4. 既存設計に沿った最小差分で実装します。
5. 必要なテストを追加・更新し、関連チェックを実行します。
6. 差分をレビューし、要求漏れ、回帰、不要な整形や無関係な変更を除きます。
7. 結果、変更点、検証、残るリスクを報告します。

大規模または長時間の変更では、実装前に計画と検証方法を明確にします。複数ターンや引き継ぎで
判断がずれる可能性がある場合は、対象プロジェクトの方式に従って計画文書を作成し、作業中に
進捗と判断を更新します。
